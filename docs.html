Quickstart

Install to a real cross-agent result in under five minutes — every command below is copy-paste, nothing to configure first.

  1. Sign in at onebrain.apxlbz.com with Google. A personal memory exists immediately — no setup, no source connections, no API keys.
  2. Connect an agent, for example Claude Code: 
    claude mcp add --transport http onebrain https://qlpfjeciekaqzribxlnp.supabase.co/functions/v1/mcp
    run /mcp, choose onebrain, and approve the Google sign-in. See Connect OneBrain to Claude for every client, and Other assistants for everything else.
  3. Tell one agent something (“remember that launch moved to October 14”), then ask a different agent about it. Same memory, every agent.

This exact remember → recall round trip, with provenance, is what scripts/v1_smoke/launch_check.py checks against a live deployment on every release; running the one-liner above from a clean machine is that script’s manual checklist item 2e.

What OneBrain is

OneBrain is one long-term memory that every AI agent you use — Claude, ChatGPT, Cursor, your own agents — reads and writes through one standard MCP endpoint. What one agent learns, the others can recall: a preference, a decision, a fact about a project. Every fact keeps the agent that wrote it and when.

Every sign-in gets a private memory of its own, work address or personal: nobody else, not even a coworker on the same domain, can reach a single row. Organizations that set up a shared domain memory before this changed keep it as a shared space; members reach it by adding ?space=<domain> to the connector URL.

OneBrain does not read your Gmail, Calendar, Drive or Trello on its own. Memory comes only from what you and your agents explicitly remember — through a conversation, a hook, or the Memory.md file every connected agent follows.

Other assistants

Any MCP client that speaks streamable HTTP takes the same address. Cursor, VS Code, Windsurf, and Gemini CLI setups are filled in for you on the setup wizard’s Done step, including one-click links for Cursor and VS Code. Scripts and hooks authenticate with a personal token, minted on the same page or in Settings, sent as Authorization: Bearer <token>.

Memory.md is the portable half of the product: a short instruction file that teaches any agent when to call recall and remember, even where the MCP server’s own instructions are ignored. Download your personalised copy from GET /functions/v1/api/memory.md (Bearer token required) or from Settings, and drop it where your agent reads instructions (CLAUDE.md @import, AGENTS.md, a ChatGPT/Grok custom instruction, a system prompt).

API reference

Everything the MCP tools do is also plain REST, for agents and scripts that don’t speak MCP. Base URL: 

https://qlpfjeciekaqzribxlnp.supabase.co/functions/v1/api
Every call carries Authorization: Bearer <token> — a personal token (Settings, or POST /v1/me/token from a signed-in session) or a Supabase session JWT. A shared space is selected with ?space=<domain> or an X-OneBrain-Space header; omit both for your personal memory.

POST /v1/recall

Search the memory.

curl -X POST "$BASE/v1/recall" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"query": "pricing decision", "limit": 5}'

Body: query (required), limit (default 5), source, type. Returns { results: [{ id, content, type, source, created_at, score, … }] }.

POST /v1/remember

Store a durable fact, preference or decision.

curl -X POST "$BASE/v1/remember" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"content": "The launch moved to October 14."}'

Body: content (required), replaces (ids this supersedes), type. A quick durability check runs first; trivial or one-off chatter is gated and not stored ({ stored: false, gated: true }). Otherwise returns { stored: true, facts: [{ id }], enrichment: "pending" } immediately — the fact is recallable right away; richer extraction finishes in the background.

POST /v1/forget

Permanently delete memories. Irreversible.

curl -X POST "$BASE/v1/forget" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"ids": ["<fact-id>"]}'

Body: ids (uuid array) or contains (a text match, ≥ 3 characters). A contains match over the safety threshold is refused unless resent with "confirm": true; pass "dry_run": true to preview first.

POST /v1/feedback

Rate a recalled fact 1–5 so ranking learns what was useful: {"fact_ids": ["<id>"], "rating": 5}.

GET /v1/export

Your whole memory as portable JSON — raw inputs, derived facts, entities, relationships, summaries. Embeddings are omitted (reproducible, provider-specific); forgotten content is left out.

POST /v1/me/token

Mint a personal API token (needs a signed-in session, e.g. a web cookie or OAuth JWT, not another static token). Minting again replaces the previous token: { token, note: "shown once…" }.

Architecture

OneBrain runs entirely on Supabase: Postgres with pgvector for storage, Edge Functions (Deno) for every server surface, and GoTrue for auth (Google sign-in, plus MCP OAuth 2.1).

  • Write path (remember). The input is stored verbatim first — immutable, deduplicated by source reference — and is recallable within the same request. In the background, an LLM (DeepSeek, the platform engine) splits it into atomic facts with entities and relationships, embeds them (Qwen3, 1024-d), and a judge retires any fact they contradict.
  • Read path (recall). A query is embedded and matched against the memory with hybrid semantic (pgvector cosine) and lexical (Postgres full text) search, fused and re-ranked by recency, importance, and feedback learned from ratings.
  • Tenancy. Every sign-in gets its own memory (user:<email>), isolated by row-level security keyed off the authenticated caller; domain-shared memories created before this model are kept as opt-in shared spaces.
  • Ingestion. There is currently no automatic ingestion from third-party sources (Gmail, Calendar, Trello, …); every fact comes from an explicit remember call by a connected agent, hook, or the import tool. A background worker (pg_cron, every 30s) only self-heals writes whose enrichment didn’t finish.
  • Billing. Free / Pro / Team plans are prepaid platform credit; usage is metered per model call.

Deeper design history, including diagrams, lives in the repository’s docs/ directory for anyone with access to the codebase.

FAQ

Is this a team tool or a personal one?

Personal, by default: every sign-in gets its own private memory, and no setup is required to start using it. Organizations that already share a domain memory keep it as an opt-in shared space.

Does OneBrain read my Gmail, Calendar or Trello automatically?

No. Automatic ingestion from third-party sources is currently off. Memory is built only from what you and your agents explicitly remember — in conversation, through a hook, or via the import tool.

Can two of my agents see the same memory?

Yes — that is the point. Connect Claude, ChatGPT, Cursor, or any MCP-capable agent to the same endpoint and sign-in; what one remembers, the others can recall.

Can a coworker read my memory?

No, unless you were already part of a shared domain space before the personal-by-default model. A fresh sign-in is always private, even to coworkers on the same email domain.

How do I remove something?

Ask an agent to forget it, call POST /v1/forget, or use the dashboard. Deletion is permanent and cascades to everything derived from that input.

What does it cost?

Free includes 500 facts and 2 connected agents. Pro and Team add higher limits and per-seat pricing; both run on prepaid platform credit metered per model call. See Settings → Billing for current numbers.

Can I self-host OneBrain?

Not currently. It runs on a managed Supabase project; there is no self-hosted or on-prem edition.

Is my data used to train models?

No. See Your data and the full Privacy policy.

Your data

  • Personal by default. A fresh sign-in creates a private memory only you (and the agents you connect) can read or write.
  • No source access unless you grant it. OneBrain does not read Gmail, Drive, Calendar or Trello on its own; any legacy connection from before this model was read-only and could not modify or delete anything at the source.
  • Google user data is handled under the Google API Services User Data Policy, including the Limited Use requirements. It is never sold or used for advertising.
  • Secrets are stripped on the way in: API keys, passwords, and tokens are never written to memory.
  • You can take it all back. Settings offers a full JSON export, a one-click purge of the memory, and deletion of the organization, which revokes any connected source’s access at the provider.

Troubleshooting

  • “Couldn’t reach the MCP server.” Check the address ends in /functions/v1/mcp with no trailing slash.
  • The sign-in loops. Sign in at onebrain.apxlbz.com first with the same Google account, then connect again.
  • Answers are empty. A fresh memory has nothing in it yet: ask an agent to remember something, or run the import tool, then recall again.
  • A legacy source connection shows “error”. New source connections are not offered under the current model; an existing one can be re-checked from Setup → Sources.
  • Anything else: or@apxlbz.com.
